# Risks and mitigations

| Risk | V1 mitigation |
|---|---|
| Direct mobile access tempts unsafe public exposure | Keep V1 beta same-device and Core on `127.0.0.1`; never open a port automatically; require a separate post-V1 pairing/TLS/revocation/recovery decision |
| Automatic maintenance applies a false or stale observation | Let only Core decide; use server-derived origin, explicitness, versioned deterministic policy, memory-slot conflict rules, provenance, immutable history, optional activity inspection, and reversible correction/forget/restore |
| A model inference masquerades as a user fact | Authentication alone does not grant explicitness; only an ATC-configured same-device principal with the explicit-statement witness grant may attest direct user text. Inference remains tentative and an authorized malicious client remains a documented residual risk |
| The absence of routine review hides a policy defect | Record `policy_version`, decision reason, origin, timestamps, and evidence links; expose optional activity and undo; make migrations idempotent; test decision matrices and replay determinism |
| A client reads records outside its authority | Authenticate scoped client identities and apply permissions, applied disposition, validity, deletion, and supersession before every retrieval channel |
| A managed client attaches to the wrong Core | Bind generated configuration to the exact data directory, instance proof, port, client ID, and credential |
| Large or malicious imports exhaust resources | Chunk HTTP/raw SQLite writes, stream top-level conversation arrays, enforce entry/raw/expanded-size/compression bounds, and use resumable batches |
| Provider archive prose or assistant output injects false context | Treat all imported text as inert data; normalize and exclude assistant/system/tool/attachment roles; keep generic instruction-bearing text and provider-synthesized memory tentative; publish no current change before successful extraction |
| Provider role labels are wrong | Preserve byte-exact source and message provenance, use conservative parser-specific origin rules, retain bounded policy reasons, and make ordinary automatic changes reversible |
| Undocumented provider schema changes silently omit history | Preserve the complete raw archive, publish detected counts/warnings/limitations, fail coverage closed on parse errors, and version parsers for later reprocessing |
| Interrupted migration, policy evaluation, export, shutdown, or update corrupts state | Use SQLite transactions/backups, portable locks, idempotency keys, journals, health checks, and tested rollback paths |
| Credentials or raw personal context leak through logs, browser state, or configuration | Use OS credential abstractions, opaque one-use browser sessions, redaction, no raw-context logging, and least-privilege tokens |
| Secret-like direct content is marked ignored but remains in the vault, backup, or a guessable hash | Refuse or irreversibly redact before durable storage; forbid unkeyed payload fingerprints; use opaque/keyed idempotency; rebuild/compact affected state; scan synthetic canaries across SQLite pages/freelists, WAL/journal, FTS, temp state, diagnostics, export, and restore; warn that external historical backups require retirement |
| Unsigned community packages are mistaken for publisher-signed software | Prominent unsigned labels plus checksums, SBOM/provenance, immutable assets, and offline Ed25519 update manifests |
| Supported cross-platform scope exceeds evidence | Keep the Windows/Linux release matrix explicit, require clean-machine exact-artifact receipts in both supported families, keep retained Mac source/tests and historical evidence outside ordinary CI and release evidence, and leave beta in draft if any supported receipt is missing |
| Live SQLite is readable to the OS account | Document the boundary; rely on account/disk protection; encrypt portable exports |
| Active Edge compatibility APIs outlive the Core-only product claim | Remove or build-gate enrollment, connect, sync, mutation triggers, and normal CLI paths from supported artifacts; retain only an isolated, tested legacy cleanup path |
| A newer database or export is accepted as if it were compatible | Give schema and migration files stable identities, reject newer unsupported schemas, publish an export compatibility range, and make dry-run restore exercise a disposable full vault |
| Credential fallback silently weakens storage or setup leaves an orphaned principal | Require explicit protected-fallback policy, avoid bearer tokens in ordinary configuration, and roll back newly created principals when client configuration fails |
| Contradictory imported facts remain current because they lack an entity/attribute slot | Define versioned contradiction and slot semantics for real provider shapes; replay chronological fixtures and preserve provenance/history |
| The mandatory 2 GB import boundary exceeds real resource evidence | Enforce the frozen 4-core/8-GiB/SSD/16-GiB-free, 1-GiB RSS, four-times-source-plus-1-GiB storage, 5-second progress/cancel, 30-second quiescence, and 60-minute-per-operation profile. Require an allocated non-sparse nonempty canary, exact success on Windows x86-64 and Linux x86-64, boundary-plus-one refusal, SHA, packaged export/restore, and interruption recovery; leave beta in draft until both pass |
| A beta candidate resolves different dependencies or omits component evidence | Require the exact green source SHA, locked dependency composition, generated-dashboard parity, complete component/license inventory, and reproducibility comparison |
| Release or repository controls allow an unreviewed change or secret to reach users | Use the enabled private vulnerability intake, protect feasible branches/environments, enable available secret/dependency/code scanning, and record sole-maintainer plus AI-assisted review without claiming independence |
| Real provider exports drift beyond synthetic parser coverage or a trivial export passes | Identify each parser independently, acquire nonempty exports after parser freeze and within 30 days, maintain frozen fictional shape sets, reconcile every item to closed coverage outcomes, and require ChatGPT/Claude/Grok receipts; leave beta in draft if any is missing |
| Backup/restore or purge is available only to contributors | Packaged recovery/admin helper or native mode is integrated in every supported artifact; prove exact downloaded-artifact stopped-Core restore and deliberate administrator purge without Python/source on Windows and Linux before publication |
| Stable release metadata remains beta-specific or unrecoverable | Treat the stable trust root/channel/publish path as post-V1; before stable, add verified key backups, rehearsal, recovery, and incident/key-rotation drills |
| Legacy `always_available` records imply an offline guarantee | Label them legacy, do not offer the value for new current context, and let users migrate them to `core_available` |
