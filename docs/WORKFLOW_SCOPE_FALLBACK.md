# Qualified workflow capture boundary

This isolated repair depends on the unmerged personal correction/chronology
candidate `5b6d6e2415208d00cd1a99e7a96c76729fdbf058`. It does not include the
separate purge/replay repair, change storage or schema, or integrate into the
original repository.

The existing live-user workflow extractor accepted `We use DuckDB for Juniper.`
as global `user/tooling` memory. A second unbound client naming another project
could replace that same record, and an unrelated empty-query reader could receive
the project statement. A mentioned name cannot provide canonical project authority.

After the existing whole-turn first-person workflow match, automatic extraction
now refuses a complete workflow value with a whitespace-delimited `for`, `in`,
`on`, `within` or `across` qualification. This applies to `I/We use` and
`My/Our workflow/stack is` forms, independent of tool or target names. The only
exception is one terminal qualification whose complete complement is exactly
`all projects`, `every project`, or `each project`, ignoring case after existing
NFKC/whitespace normalization. The earliest qualifier is matched, so a nested
project qualifier or appended exception cannot acquire global meaning from a
later suffix.

This is conservative refusal of an entire claim. No target substring is extracted
or resolved, no project is manufactured, and no grant comes from a reader hint.
Ambiguous purpose wording such as `I use Python for scripting` and
`My workflow is based on Python` remains tentative raw evidence. Unqualified
`We use Python.` and `My workflow is terminal based.` still form, as do explicit
global controls such as `We use Python for all projects.`. Personal preference
facets, including `I prefer tabs for code indentation.`, are unchanged.

Supported named/current-project decisions still use the separate transaction-
resolved canonical binding and existing role/value policy. A qualified workflow
without an admissible decision does not become a scoped decision by inference,
even when its writer is bound. Capture retains exact raw content, source provenance,
existing bound raw scopes, and the original replay receipt.
